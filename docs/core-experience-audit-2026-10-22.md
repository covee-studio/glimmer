# Glimmer 核心体验审查（2026-10-22）

## 结论与范围

主页已有清楚的气质，本轮不需要重新设计。优先问题是加载失败后的恢复、收藏的查找与撤销、键盘操作，以及连接页中过大的品牌区域。应先处理这些，再增加主题或声音。

本轮依据本地网页版的真实 Hacker News、Wikipedia 内容、实际截图、键盘操作和页面状态。它不代表 Chrome 商店版已完成验收，也不是无障碍合规认证。原主题、数据源开关和收藏数量已恢复；测试浏览自动增加的最近记录仍保留，没有清空原历史。没有输入或披露密钥，没有断开任何账号。

## 按影响排序的问题

| 优先级 | 问题 | 本轮处理 |
| --- | --- | --- |
| 高 | 百科请求可能一直等待，离开来源后也未取消 | 增加时限、取消和定时器清理；新增两个回归测试。 |
| 高 | 最后一个来源开关被无声拒绝 | 保留保护规则，增加解释。 |
| 高 | 移除、撤销收藏时键盘焦点丢失 | 焦点跟随操作及恢复后的条目。 |
| 中 | 搜索缺少恢复入口，旁边仍有清空历史 | 增加清除搜索；筛选期间隐藏批量操作。 |
| 中 | 标签页与弹窗语义、键盘操作不完整 | 补齐方向键、Home/End、焦点顺序、标签页关联和弹窗名称。 |
| 中 | 最近记录信息重复，标题不突出 | 精简可见元信息，保留数据及收藏摘要。 |
| 中 | 配置页更像宣传页，填写任务靠后 | 缩小标识，调整对齐和间距。 |
| 低 | 英文界面日期受系统语言影响 | 明确使用英文日期格式，与现有界面策略保持一致。 |
| 低 | 加载动画缺少可访问名称 | 增加读屏状态，不增加可见说明。 |

## 后续处理顺序与验收边界

本节为首次审查时的顺序；内容适配、超时恢复及本地插件同步开关的后续结果见 [第二轮验收](content-and-extension-review-2026-10-22.md)。

1. **内容适配**：继续检查 Memos 长笔记、微信读书划线与读后感、Hypothesis 注释，以及不同比例的图片。区分示例内容排版检查与真实账号端到端验证，不读取或披露密钥。
2. **失败与恢复**：用受控断网、HTTP 错误检查最终错误页和重试。当前只完成了超时、取消的单元测试，不能据此宣称实际错误页面已验收。
3. **Chrome 插件验收**：同步开关、多标签页、可选权限、已安装插件的真实动画。网页版通过、插件能构建，都不能替代这一步。
4. **无障碍**：实际读屏、对比度、缩放及完整键盘走查。本轮语义修复不等于已认证。
5. **主题基准**：保持数量稳定，以成熟主题为参照，统一空间、细节密度和运动节奏。本轮不增加声音或继续重画主题。

所有改动仍在 `codex/nature-themes`。没有合并、改版本号、推送、提交商店或发布。
